# Полное описание логики работы программы классификации судов

## 1. Общее назначение системы

Программа предназначена для автоматической классификации водных транспортных средств (судов, кораблей, лодок и плавучих конструкций) на основе текстового описания. Система использует иерархическую структуру правил, основанную на ОКПД2 (Общероссийский классификатор продукции по видам экономической деятельности), и реализует два подхода к классификации:

- **Иерархический подход** — поэтапное прохождение по уровням иерархии от общего к частному
- **Классический подход** — одновременная оценка всех правил и выбор наилучшего совпадения

| `RulesReader` | Загрузка и управление правилами из JSON |

## 3. Поток данных (Data Flow)

### 3.1. Общая последовательность обработки

```
Входной текст
     ↓
TextPreprocessor.preprocess()
     ↓
Сырые термины + Числовые значения
     ↓
FeatureExtractor.extract_features()
     ↓
Структурированные признаки (features)
     ↓
InferenceEngine.classify()
     ↓
Результат классификации
```

### 3.2. Детальный пошаговый процесс

#### Шаг 1: Инициализация компонентов

При запуске программы создаются три основных объекта:

```python
text_preprocessor = TextPreprocessor()
feature_extractor = FeatureExtractor()
classifier = VesselClassifier()
```

`VesselClassifier` при инициализации:
- Загружает правила через `RulesReader.get_rules()`
- Создаёт `FeatureExtractor` для извлечения признаков
- Создаёт `InferenceEngine` с загруженными правилами

#### Шаг 2: Предобработка текста (TextPreprocessor)

**Метод:** `preprocess(text: str) -> Dict[str, Any]`

**Подшаги:**

1. **Токенизация** (`tokenize`)
   - Приведение к нижнему регистру
   - Удаление специальных символов (кроме букв, цифр, пробелов, дефисов)
   - Замена дефисов на подчёркивания
   - Разбиение на токены по пробелам
   
   *Пример:* `"Круизное морское судно"` → `["круизное", "морское", "судно"]`

2. **Извлечение чисел** (`extract_numbers`)
   - Поиск паттернов с единицами измерения:
     - Тоннаж: `(\d+(?:\.\d+)?)\s*(?:тонн|т)`
     - Вместимость: `(\d+)\s*(?:пассажиров|пасс|чел)`
     - Длина: `(\d+(?:\.\d+)?)\s*(?:метров|м)`
     - Грузоподъёмность: `(\d+(?:\.\d+)?)\s*(?:грузоподъемность|грузоподъемностью)`
   
   *Пример:* `"150 пассажиров, 50 тонн"` → `{'вместимость': 150.0, 'тоннаж': 50.0}`

3. **Удаление стоп-слов** (`remove_stopwords`)
   - Использование списка стоп-слов NLTK для русского языка
   - Фильтрация токенов короче `min_len_token` (по умолчанию 3 символа)
   - Дополнительные стоп-слова: `'быть'`, `'ходить'`

4. **Лемматизация** (`lemmatize`)
   - Использование `pymorphy3` (или `pymorphy2`) для приведения слов к нормальной форме
   - Каждый токен разбирается морфологически, извлекается лемма
   
   *Пример:* `["круизные", "морские", "суда"]` → `["круизный", "морской", "судно"]`

5. **Извлечение составных терминов** (`extract_composite_terms`)
   - Поиск биграмм и триграмм в словаре `composite_lemmas`
   - Замена составных терминов на канонические формы с подчёркиваниями
   
   *Примеры из словаря:*
   - `"сжиженный газ"` → `"сжиженный_газ"`
   - `"буксир толкач"` → `"буксир_толкач"`
   - `"природный газ"` → `"природный_газ"`

6. **Нормализация синонимов** (`normalize_synonyms`)
   - Замена синонимов на канонические термины ОКПД2
   - Исключение слов, уже вошедших в составные термины
   
   *Примеры из словаря:*
   - `"корабль"` → `"суда"`
   - `"пассажир"` → `"пассажирские"`
   - `"танкер"` → `"танкеры"`
   - `"круизный"` → `"круизные"`

**Выходные данные предобработки:**
```python
{
    'original_text': str,           # Исходный текст
    'tokens': List[str],            # Токены после токенизации
    'filtered_tokens': List[str],   # Токены без стоп-слов
    'lemmas': List[str],            # Лемматизированные токены
    'composite_terms': List[str],   # Найденные составные термины
    'normalized_terms': List[str],  # Все термины после нормализации
    'numbers': Dict[str, float],    # Извлечённые числовые значения
    'used_words': Set[str]          # Слова, использованные в составных терминах
}
```

#### Шаг 3: Извлечение признаков (FeatureExtractor)

**Метод:** `extract_features(text: str) -> Dict[str, Any]`

**Процесс:**

1. Вызов `preprocessor.preprocess(text)` для получения сырых данных
2. Определение типа судна через `extract_vessel_type()`
3. Извлечение атрибутов через `extract_attributes()`
4. Преобразование числовых значений через `extract_numbers()`

**3.1. Определение типа судна (`extract_vessel_type`)**

Словарь `term_to_vessel_type` сопоставляет термины с типами судов:

| Термин | Тип судна |
|--------|-----------|
| `"корабли"`, `"ship"` | `Ship` |
| `"лодки"`, `"boat"` | `Boat` |
| `"пассажирские"`, `"cruise"` | `PassengerBoat` |
| `"танкеры"`, `"tanker"` | `Tanker` |
| `"газовозы"` | `GasCarrier` |
| `"сухогрузные"` | `DryCargoBoat` |
| `"контейнерные"` | `ContainerShip` |
| `"рыболовные"` | `FishingBoat` |
| `"буксиры"` | `TugBoat` |
| `"земснаряды"` | `Dredger` |
| `"платформы"` | `Platform` |
| `"прогулочные"` | `RecreationalBoat` |

Возвращает первый найденный тип или `'Boat'` по умолчанию.

**3.2. Извлечение атрибутов (`extract_attributes`)**

Заполняет словарь атрибутов на основе найденных терминов:

- **`navigation_area`** (зона плавания): из `term_to_navigation_area`
  - `"морские"`, `"речные"`, `"озерные"`, `"смешанного"` (река-море)

- **`purpose`** (назначение): из `term_to_purpose`
  - `"военные"`, `"пассажирские"`, `"грузовые"`, `"рыболовные"`, `"буксиры"`, `"спасательные"`, `"спортивные"`, `"прогулочные"`

- **`cargo_type`** (тип груза): из `term_to_cargo_type`
  - `"пассажиров"`, `"нефти"`, `"сжиженных"`, `"контейнерные"`, `"навалочных"`, `"лесовозы"`

- **`specialization`** (специализация): из `term_to_specialization`
  - `"круизные"`, `"паромы"`, `"траулеры"`, `"сейнеры"`, `"рыбозаводы"`, `"земснаряды"`, `"пожарные"`

**3.3. Числовые атрибуты (`extract_numbers`)**

Преобразует извлечённые числа в стандартные атрибуты:

| Исходное | Целевой атрибут |
|----------|----------------|
| `тоннаж` | `tonnage` |
| `вместимость` | `passenger_capacity` |
| `длина` | `length` |
| `грузоподъемность` | `cargo_capacity`, `deadweight` |

**Выходные данные извлечения признаков:**
```python
{
    'original_text': str,              # Исходный текст
    'raw_terms': List[str],            # Нормализованные термины
    'vessel_type': str,                # Тип судна (например, "PassengerBoat")
    'attributes': {                    # Словарь атрибутов
        'navigation_area': str,        # Зона плавания
        'purpose': str,                # Назначение
        'cargo_type': str,             # Тип груза
        'specialization': str          # Специализация
    },
    'numeric_attributes': {            # Числовые характеристики
        'tonnage': float,
        'passenger_capacity': float,
        'length': float,
        'cargo_capacity': float
    }
}
```

#### Шаг 4: Загрузка правил (RulesReader)

**Метод:** `get_rules() -> List[dict]`

Правила загружаются из файла `data/cnl_rules_full.json`.

**Структура правила:**
```json
{
  "code": "30.11.1",
  "name": "Корабли военные",
  "parent_code": "30.11",
  "level": 3,
  "rule": {
    "type": "necessary_and_sufficient",
    "conditions": [
      {
        "attribute": "is_instance_of",
        "operator": "equals",
        "value": "Ship"
      },
      {
        "attribute": "purpose",
        "operator": "equals",
        "value": "военные"
      }
    ],
    "description": "Объект является военным кораблем"
  }
}
```

**Поля правила:**
- `code` — уникальный код классификации (иерархический)
- `name` — человеко-читаемое название
- `parent_code` — код родительского правила (null для корневых)
- `level` — уровень в иерархии (1 = самый общий)
- `rule.conditions` — список условий для匹配
- `rule.type` — тип правила (обычно `necessary_and_sufficient`)

**Индексация правил в InferenceEngine:**
- `rules_by_code` — словарь для быстрого доступа по коду
- `rules_by_parent` — словарь потомков для каждого родителя
- `root_rules` — список корневых правил (уровень 1, без parent_code)

#### Шаг 5: Оценка правил (RuleMatcher)

**Метод:** `evaluate_rule(rule: dict, features: dict) -> Tuple[bool, float]`

Возвращает:
- `is_matched` — `True`, если все условия выполнены (match_ratio == 1.0)
- `match_ratio` — доля выполненных условий (от 0.0 до 1.0)

**5.1. Оценка отдельного условия (`evaluate_condition`)**

Поддерживаемые операторы:

| Оператор | Описание | Пример |
|----------|----------|--------|
| `equals` | Равно | `attr == value` |
| `not_equals` | Не равно | `attr != value` |
| `in` | Принадлежность | `attr in [list]` |
| `not_in` | Не принадлежит | `attr not in [list]` |
| `greater_than` | Больше | `attr > value` |
| `less_than` | Меньше | `attr < value` |
| `contains` | Содержит | `value in attr` |
| `exists` | Существует | `attr is not None` |
| `not_exists` | Не существует | `attr is None` |

**Особенности оценки:**

1. **Атрибут `is_instance_of`** — специальное отображение на `vessel_type` из признаков
   - Поддержка fallback на атрибут `purpose` для значения `"пассажирское"`

2. **Регистронезависимое сравнение** — для строковых значений
   - `"Пассажирское".lower() == "пассажирское".lower()`

3. **Иерархия типов для оператора `in`**:
   - Если правило требует `["Ship"]`, а извлечён тип `PassengerBoat`, условие считается выполненным
   - Иерархия: `PassengerBoat → Ship`, `Tanker → Ship`, `Ferry → Ship` и т.д.
   - Все типы судов наследуются от `Vessel`

**5.2. Оценка логических блоков (`evaluate_logic`)**

Поддержка композиций условий:

```json
{
  "logic": "AND",
  "conditions": [...]
}
```

или

```json
{
  "logic": "OR",
  "conditions": [...]
}
```

- **AND** — все условия должны быть истинны
- **OR** — хотя бы одно условие должно быть истинно

**5.3. Расчёт match_ratio**

```python
match_ratio = matched_conditions / total_conditions
```

- Правило считается полностью совпавшим (`is_matched = True`), если `match_ratio == 1.0`
- Частичные совпадения с `match_ratio > 0.5` также учитываются при поиске альтернатив

#### Шаг 6: Логический вывод (InferenceEngine)

**Метод:** `classify(text: str, feature_extractor: FeatureExtractor, use_hierarchical: bool) -> dict`

**6.1. Кэширование**

Для иерархического подхода результаты кэшируются по ключу:
```python
cache_key = f"hierarchical:{text}"
```

**6.2. Иерархическая классификация (`_classify_hierarchical`)**

Алгоритм поэтапного прохождения по уровням:

```
1. Начать с корневых правил (level 1)
2. Найти лучшее правило на текущем уровне:
   - Перебрать все правила уровня
   - Оценить каждое правило через RuleMatcher.evaluate_rule()
   - Выбрать правило с максимальным match_ratio > 0.5
   - При равенстве match_ratio выбрать правило с большим level (более специфичное)
3. Если лучшее правило найдено:
   - Добавить его в путь классификации
   - Перейти к потомкам этого правила (правила следующего уровня)
   - Повторить шаг 2
4. Если правило не найдено — остановить обход
```

**Путь классификации** — список от корня до листа:
```python
[
    {'code': '30.1', 'name': 'Корабли, суда и лодки', 'match_ratio': 1.0, 'level': 1},
    {'code': '30.11', 'name': 'Корабли, суда и плавучие конструкции', 'match_ratio': 1.0, 'level': 2},
    {'code': '30.11.3', 'name': 'Суда пассажирские', 'match_ratio': 1.0, 'level': 3},
    {'code': '30.11.31', 'name': 'Суда круизные', 'match_ratio': 1.0, 'level': 4}
]
```

**6.3. Классическая классификация**

Если `use_hierarchical = False`:
- Выполняется оценка всех правил через `rule_matcher.match_rules(features)`
- Путь классификации остаётся пустым
- Лучшее правило выбирается по максимуму `(match_ratio, level)`

**6.4. Формирование результата**

```python
result = {
    'original_text': str,              # Исходный текст
    'features': dict,                  # Извлечённые признаки
    'matched_rules': List[dict],       # Все совпавшие правила (match_ratio > 0.5)
    'best_match': dict,                # Лучшее правило
    'confidence': float,               # Уверенность (match_ratio лучшего правила)
    'alternatives': List[dict],        # Альтернативные варианты (ratio >= 0.7)
    'classification_path': List[dict]  # Путь иерархической классификации
}
```

**Выбор лучшего правила:**

- **Иерархический подход**: последнее правило в `classification_path` (самое специфичное)
- **Классический подход**: правило с максимальным `match_ratio`, при равенстве — с большим `level`

**Альтернативы:**
- До 5 лучших правил из остальных совпавших
- Только правила с `match_ratio >= 0.7`

## 4. Точка входа (main.py)

```python
def main():
    # Инициализация компонентов
    text_preprocessor = TextPreprocessor()
    feature_extractor = FeatureExtractor()
    classifier = VesselClassifier()
    
    test_text = "Круизное морское судно для перевозки пассажиров"
    
    # Тест 1: Иерархический подход
    result_hierarchical = classifier.classify(test_text, use_hierarchical=True)
    classifier.show_result(result_hierarchical)
    
    # Тест 2: Классический подход
    result_classic = classifier.classify(test_text, use_hierarchical=False)
    classifier.show_result(result_classic)
```

**Метод `show_result`:**
Выводит в консоль:
- Оригинальный текст
- Извлечённые признаки (raw_terms, vessel_type, attributes)
- Лучшее правило (код, название, match_ratio)
- Путь классификации (для иерархического подхода)
- Все совпавшие правила

### Шаг 1: Предобработка

**Токенизация:**
```
["круизное", "морское", "судно", "для", "перевозки", "пассажиров"]
```

**Удаление стоп-слов:**
```
["круизное", "морское", "судно", "перевозки", "пассажиров"]
```
(удалено слово "для")

**Лемматизация:**
```
["круизный", "морской", "судно", "перевозка", "пассажир"]
```

**Составные термины:**
```
[]  (не найдено биграмм/триграмм из словаря)
```

**Нормализация синонимов:**
```
["круизные", "морские", "суда", "перевозки", "пассажиров"]
```

### Шаг 2: Извлечение признаков

**vessel_type:**
- Найдено `"круизные"` → `"PassengerBoat"`

**attributes:**
- `navigation_area`: `"морские"` → `"морские"`
- `purpose`: `"пассажирские"` (из термина `"пассажиров"`) → `"пассажирские"`

**numeric_attributes:**
```
{}  (числа не найдены)
```

### Шаг 3: Классификация (иерархическая)

**Уровень 1:**
- Правило `30.1` ("Корабли, суда и лодки")
- Условие: `is_instance_of in [Vessel, Ship, Boat, ...]`
- `vessel_type = "PassengerBoat"` → условие выполнено
- `match_ratio = 1.0`

**Уровень 2:**
- Потомки `30.1`: правило `30.11` ("Корабли, суда и плавучие конструкции")
- Условие: `is_instance_of in [Ship, Boat, ...]`
- `PassengerBoat` наследуется от `Boat` → условие выполнено
- `match_ratio = 1.0`

**Уровень 3:**
- Потомки `30.11`: правила `30.11.1` (военные), `30.11.2` (грузовые), `30.11.3` (пассажирские)
- Правило `30.11.3`: условия `purpose == "пассажирские"`
- `attributes['purpose'] = "пассажирские"` → условие выполнено
- `match_ratio = 1.0`

**Уровень 4:**
- Потомки `30.11.3`: правила `30.11.31` (круизные), `30.11.32` (паромы)
- Правило `30.11.31`: условия `specialization == "круизные"`
- Найдено `"круизные"` в терминах → `specialization = "круизные"`
- `match_ratio = 1.0`

**Уровень 5:**
- Потомков у `30.11.31` нет → остановка

**Путь классификации:**
```
30.1 → 30.11 → 30.11.3 → 30.11.31
```

**Лучшее правило:**

## 7. Сравнение подходов классификации

| Характеристика | Иерархический | Классический |
|---------------|---------------|--------------|
| **Порядок оценки** | По уровням от общего к частному | Все правила одновременно |
| **Выбор лучшего** | Последнее в пути (самое глубокое) | Максимальный match_ratio + level |
| **Путь классификации** | Заполнен | Пустой |
| **Кэширование** | Включено | Отключено |
| **Интерпретируемость** | Высокая (видна вся цепочка) | Средняя (только лучшее правило) |
| **Производительность** | Быстрее (оценка части правил) | Медленнее (оценка всех правил) |

## 8. Расширяемость системы

### 8.1. Добавление новых правил

1. Отредактировать `data/cnl_rules_full.json`
2. Добавить новое правило с указанием:
   - Уникального `code`
   - `parent_code` для привязки к иерархии
   - `level` (должен быть на 1 больше родителя)
   - Условий в формате CNL

### 8.2. Добавление синонимов

Отредактировать словарь `synonyms` в `TextPreprocessor`:
```python
self.synonyms = {
    'новый_синоним': 'канонический_термин',
    ...
}
```

### 8.3. Добавление составных терминов

Отредактировать словарь `composite_lemmas` в `TextPreprocessor`:
```python
self.composite_lemmas = {
    'составной термин': 'canonical_form',
    ...
}
```

### 8.4. Добавление новых атрибутов

1. Добавить маппинг в `FeatureExtractor`:
   ```python
   self.term_to_new_attribute = {
       'термин': 'значение',
       ...
   }
   ```
2. Добавить извлечение в `extract_attributes()`
3. Добавить условия в правила JSON

## 10. Ограничения и допущения

1. **Язык:** Система оптимизирована для русского языка
2. **Токенизация:** Простая, по пробелам (без учёта сложных случаев)
3. **Лемматизация:** Зависит от качества pymorphy3
4. **Числа:** Извлекаются только явные числовые значения с единицами измерения
5. **Правила:** Требуется ручное поддержание консистентности иерархии
6. **Кэширование:** Работает только для иерархического подхода

## 12. Заключение

Система представляет собой гибкий фреймворк для классификации судов на основе текстовых описаний. Ключевые преимущества:

- **Иерархическая структура** — соответствует ОКПД2, обеспечивает интерпретируемость
- **Гибкость** — поддержка двух режимов классификации
- **Расширяемость** — простое добавление правил, синонимов, атрибутов
- **NLP-обработка** — лемматизация, нормализация, извлечение чисел

Архитектура следует принципу разделения ответственности: каждый модуль отвечает за свой этап обработки, что упрощает тестирование, поддержку и развитие системы.
